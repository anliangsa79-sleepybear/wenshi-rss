# 做网页原型时别先装一堆软件：5个免费入口把想法跑起来

![做网页原型时别先装一堆软件：5个免费入口把想法跑起来](资源伸手党·成稿·05·网页原型·20261023-1030.png)

有时你并不是要立刻做一个完整产品，只是想确认一个按钮、一个页面或一段交互到底长什么样。这个时候，先打开浏览器比先装软件更快。下面 5 个入口可以按“写一点—跑起来—查清楚—画出来”的顺序使用。

**1. CodePen**  https://codepen.io/

想快速试一个网页效果，先从 CodePen 开始。HTML、CSS、JavaScript 分栏放在同一个编辑器里，改完就能看预览。它适合做按钮、卡片、动画和小组件原型，最大的优点是反馈快；不适合直接承载重要生产代码。先做一个最小效果，比打开空白项目更容易判断想法是否成立。

**2. Replit**  https://replit.com/

如果原型需要多个文件、后端或更完整的运行环境，可以看看 Replit。它把编辑器、运行和项目文件放在网页里，适合把一个小想法继续往可运行项目推进。免费层、运行资源和协作能力会受账户方案影响，打开后先看当前工作区提供什么，不要把“能打开”理解成无限使用。

**3. MDN Web Docs**  https://developer.mozilla.org/en-US/

做到一半遇到“这个属性到底怎么写”，去 MDN 查原文。先从 HTML、CSS 或 JavaScript 的学习区进入，再看示例、浏览器兼容性和参数说明。它不像教程平台那样替你排好一条轻松路线，却会把浏览器真正支持什么写得更清楚，适合核对而不是漫无目的地刷页面。

**4. DevDocs**  https://devdocs.io/

需要在几份文档之间来回切换时，DevDocs 的侧边目录很省事。打开后先选择需要的文档，再用搜索定位方法、属性或类名。它更像一个快速查阅台，适合已经知道要找什么的开发者；具体内容仍来自各项目文档，遇到版本差异时要回到项目官网确认。

**5. Figma**  https://www.figma.com/

如果问题不是“代码能不能跑”，而是“页面看起来顺不顺”，可以把草图放进 Figma。先画一块页面结构，再用组件和连线模拟点击路径。免费方案、文件权限和协作范围会随账户设置变化，适合先讨论结构和流程，不必一开始就把所有视觉细节做满。

这 5 个入口各管一段：CodePen 负责马上看到效果，Replit 负责继续跑项目，MDN 和 DevDocs 负责查清规则，Figma 负责把页面讲给别人看。今晚只选一个最小问题，做出能被别人点一下的版本，通常比收藏一整套工具更接近真正开始。
