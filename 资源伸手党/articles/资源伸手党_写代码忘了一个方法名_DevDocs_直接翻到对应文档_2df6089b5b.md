# 写代码忘了一个方法名，DevDocs 直接翻到对应文档

写代码时最耽误时间的，往往不是不会做，而是记得“有一个方法能做”，就是想不起它叫什么。DevDocs 适合处理这种短暂卡顿：打开网站，输入你记得的对象或关键词，直接跳到对应语言和库的文档页。

![DevDocs 文档搜索入口](资源伸手党·小功能·05·写代码忘了一个方法名，DevDocs 直接翻到对应文档·20261103-1030.png)

先不要把整句业务需求粘进去。比如你记得 JavaScript 数组里有个“查找符合条件的元素”的方法，就先搜 array、find 或 filter，再从结果里的方法名、参数和返回值判断哪个是自己要的。找到页面后，先看最小示例，再看参数说明，最后回到自己的代码里改一行测试。

DevDocs 的优势是把很多开发文档集中在一个检索入口，适合已经知道大概语言和对象的人。它不是教程，也不会替你解释完整的编程概念；如果连“数组”和“对象”的区别都不清楚，应该先看系统课程，别把文档搜索当成学习路线。

它通常不需要注册就能浏览，部分文档支持本地缓存或离线使用，但具体可用范围取决于当前页面和浏览器设置。复制示例时要注意版本：同一个方法在不同版本的库里，参数、兼容性和推荐写法可能不同。不要只看搜索结果的第一行，确认文档版本和适用环境。

最省时间的用法是“三步停”：搜索到方法名，读懂一个例子，在自己的最小代码里跑通。跑通后再回到大项目，不要一边翻几十个标签页一边猜。工具帮你找回记忆，真正的判断仍然要回到代码和报错本身。

它更适合已经会写一点代码、只是临时忘记 API 的人；初学者最好同时保留官方文档入口。搜索结果可能来自不同版本的文档，移动端也能看但代码对照不如电脑方便，复制示例后一定要在自己的运行环境里重新测试。

遇到搜索词不准确时，可以先搜对象，再搜动作，最后加上语言或库名。例如先搜 array，再看 find、map、filter 的差别。把最终用到的方法写进项目注释或自己的小抄，下次遇到同一类问题就不用重新从零搜索。
